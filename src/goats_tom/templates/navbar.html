{% load pending_requests_extras static bootstrap4 custom_filters %} {% comment %} `data-bs-toggle`, not `data-toggle`. `tom_common/base.html` loads *both* Bootstrap 4 JS (via `{% bootstrap_javascript %}`, with jQuery) and the Bootstrap 5 bundle, so the two frameworks were each claiming part of this navbar: the BS4 attributes here handed the dropdowns to Bootstrap 4, while anything written with `data-bs-` went to Bootstrap 5. That split is what broke the Manage Requests row. A single click did two things at once -- Bootstrap 4 closed the menu, because it dismisses on any click inside, while Bootstrap 5 expanded the row where nobody could see it. The row only appeared open on the *second* click. `data-bs-auto-close` could not help, since it is an option Bootstrap 5 reads and this dropdown was not Bootstrap 5's to configure. Moving the toggles to `data-bs-` gives Bootstrap 5 the whole navbar, which matches the CSS: Halfmoon is built on Bootstrap 5, so the classes here were already 5's. Both right-hand menus use `dropdown-menu-end`, Bootstrap 5's name, and must. `halfmoon.goats.css` does define its own `.dropdown-menu-right { right: 0; left: auto; }`, so under Bootstrap 4 that class was doing real work. But Bootstrap 5 positions dropdowns with Popper, in JavaScript, and Popper writes inline styles that beat a plain CSS rule. It recognises `dropdown-menu-end` and aligns the menu's right edge to the toggle; it does not recognise `dropdown-menu-right`, so it left-aligns instead -- which sends a fixed-width menu straight off the right of the window when its button sits near the edge. The lesson being: the toggle attribute and the alignment class have to agree. `data-bs-toggle` means Bootstrap 5 owns positioning, and Bootstrap 5's class names are the only ones it reads. {% endcomment %}
